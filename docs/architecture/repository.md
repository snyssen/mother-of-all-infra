# Repository Layout

How the repository is organised, and where to look for what. The tree itself is
authoritative: module and host lists below are a map, not an inventory.

## Top level

| Path | What lives there |
|------|------------------|
| `nix/` | Every NixOS / Home Manager host and module, the apps server's Docker Compose stacks, the dev shell, and flake checks and packages |
| `ansible/` | The imperative work that stays awkward in Nix: building and provisioning libvirt VM images, the Technitium DNS cluster, the bare-metal backup server. See `ansible/README.md` |
| `terraform/` | Cloud machines and their IAM: `gandi/` (OpenStack instance) and `ovh/` (VPS), each split into `bootstrap/` and `infra/` |
| `hypervisor/` | `just` recipes wrapping `virsh` over SSH to `hypervisor-01` |
| `scripts/` | Helper scripts, called from `just` recipes and devshell hooks rather than by hand |
| `docs/` | This site (mkdocs-material, navigation set explicitly in `mkdocs.yaml`; preview with `just run-docs`) |
| `justfile` | Task runner entry point; imports `ansible/ansible.just`, `nix/nix.just`, `terraform/terraform.just`, `hypervisor/hypervisor.just`. `just --list` shows every recipe |
| `.sops.yaml` | SOPS recipients per secret file group, see [Secrets](secrets.md) |
| `renovate.json5` | Renovate owns dependency bumps: flake inputs, lock file maintenance, Ansible Galaxy pins |

The split of responsibilities: Terraform creates the cloud machines, Nix configures every
host and the services on them, and Ansible only does what is imperative by nature.

## Nix

### Flake and blueprint

`flake.nix` uses [numtide/blueprint](https://github.com/numtide/blueprint) with
`prefix = "nix/"`, so the directory structure under `nix/` *is* the flake's output
structure:

| Path | Flake output |
|------|--------------|
| `nix/hosts/<host>/` | `nixosConfigurations.<host>` |
| `nix/modules/nixos/<name>` | `nixosModules.<name>` |
| `nix/modules/home/<name>` | `homeModules.<name>` |
| `nix/packages/<name>/` | `packages.<system>.<name>` (e.g. `docs`, which builds this site) |
| `nix/checks/<name>.nix` | `checks.<system>.<name>` (offline checks of apps-01's alerting config) |
| `nix/devshell.nix` | `devShells.<system>.default` |

Adding a host or module is just adding a file or directory; `flake.nix` needs no edit. The
flake also adds an overlay exposing nixpkgs-unstable as `pkgs.unstable` everywhere.

`nix/data/` and `nix/files/` hold shared data (e.g. the Syncthing device list) and
static files (wallpapers, dotfiles) imported by modules.

### Hosts (`nix/hosts/`)

Each subdirectory is one machine:

```
nix/hosts/<host>/
├── configuration.nix          # main system config: imports modules, sets options
├── hardware-configuration.nix # generated by nixos-generate-config / nixos-anywhere
├── users/
│   └── <user>.nix             # per-user Home Manager config for this host
└── data/
    └── secrets.yaml           # SOPS-encrypted secrets for this host
```

`apps-01` splits its secrets into one file per stack under `data/` instead of a single
`secrets.yaml`, and keeps its Docker Compose stacks in `compose/<stack>/` (a `default.nix`
plus a `docker-compose.yaml` each, realised as a `compose-<stack>.service` unit). See
[Services](../services/index.md).

| Host | Role |
|------|------|
| `sninful` | Primary desktop / daily driver |
| `purplehaze` | Framework laptop |
| `blackfog` | Framework desktop |
| `gaming` | Gaming PC (multi-disk LUKS setup) |
| `ingress` | Remote VPS (Gandi Cloud): public reverse proxy |
| `technitium-primary` | Technitium DNS primary (bare metal) |
| `hypervisor-01` | KVM hypervisor, see [Hypervisor](hypervisor.md) |
| `apps-01` | App server: NixOS VM on `hypervisor-01` running the Docker Compose stacks |
| `technitium-secondary` | Technitium DNS secondary: NixOS VM on `hypervisor-01` |

The one machine not in Nix is the bare-metal backup server, configured by Ansible until
it moves to NixOS (issue #52).

### NixOS modules (`nix/modules/nixos/`)

Reusable system modules, one concern per file or directory, each exposing options that
hosts enable. Grouped by concern:

| Concern | Modules |
|---------|---------|
| Disks and boot | `disko/` (layouts in `disko/layouts/`, see [Full disk encryption](../operations/disk-encryption.md)), `grub.nix`, `smart.nix` |
| Secrets and access | `sops.nix`, `openssh.nix`, `user.nix`, `tailscale.nix` |
| Networking and ingress | `traefik.nix`, `crowdsec-firewall-bouncer.nix`, `domains.nix`, `nfs-exports.nix`, `nfs-mounts.nix` |
| Virtualisation and containers | `libvirtd.nix`, `docker.nix`, `compose-stacks.nix` |
| Services | `backrest/`, `postgres-restore/`, `syncthing.nix`, `jellyfin.nix`, `argunix/`, `comin.nix` |
| Observability | `grafana-alloy.nix`, `prometheus-node-exporter.nix` |
| Nix itself | `cache.nix`, `nh.nix` |
| Desktop | `gnome/`, `cosmic/`, `stylix.nix`, `gaming/`, `nvidia.nix`, `printing.nix`, `flatpak.nix`, `sunshine.nix`, … |

Modules with their own reference page are listed under **Modules** in the navigation.

### Home Manager modules (`nix/modules/home/`)

User-level configuration, imported from a host's `users/<user>.nix`: the shell
environment (`shell/`), `git.nix`, editors and applications (`vscode.nix`, `firefox.nix`,
`ghostty.nix`, …) and `restic-dr.nix`, the last-resort restore tooling described in
[Backups](../operations/backups.md).
